# RBAC 三级角色改造任务（系统管理员 / 普通管理员 / 普通用户）

## 状态

- 状态：✅ 已完成（2026-08-12 启动，同日完成）
- 前置：SaaS 多租户改造已完成（开放注册 + tenant_id 数据隔离，见 `doc/saas-migration-tasks.md`）
- 目标：把现有两级角色（admin 超级管理员 / operator 普通操作员）细化为三级角色体系

## 需求原文（用户 2026-08-12）

> 管理员可以系统管理员，普通管理员，系统管理员可以看到所有租户的注册用户信息，而普通管理员属于企业或者租户的，租户(组织或者公司）（可以分为普通管理员和普通用户），普通管理员可以给这个租户创建普通用户，是否可以实现？

## 角色模型设计（用户确认前初稿，按此实现）

| 角色                     | 判定条件                            | 归属                  | 权限                                                                                                  |
| :----------------------- | :---------------------------------- | :-------------------- | :---------------------------------------------------------------------------------------------------- |
| **系统管理员**（平台级） | `role=admin` 且 `tenant_id IS NULL` | 平台                  | 查看**所有租户**的注册用户信息（列表带租户名）；重置密码/禁用任意租户用户；创建系统管理员（平台账号） |
| **普通管理员**（租户级） | `role=admin` 且 `tenant_id 非空`    | 所属租户（企业/组织） | 查看/管理**本租户**用户；给本租户创建**普通用户**；不能创建管理员（防提权）                           |
| **普通用户**（租户级）   | `role=operator`                     | 所属租户              | 仅业务功能（客户/邮件/潜客等），无用户管理、无系统设置                                                |

- 注册流程不变：注册 → 创建租户 + 租户管理员（普通管理员）
- 现有数据兼容：初始 admin（tenant_id=NULL）= 系统管理员；注册用户（admin+租户id）= 普通管理员；operator = 普通用户

## 设计决策

| 决策点   | 结论                                                                                                                 |
| :------- | :------------------------------------------------------------------------------------------------------------------- |
| 角色字段 | 复用现有 `role` 列（admin/operator），不新增枚举；**平台/租户管理员用 tenant_id 是否为 NULL 区分**，避免迁移存量数据 |
| 权限校验 | 后端新增 `requireSystemAdmin`（平台级）+ 保留 `requireAdmin`（租户级管理员）；用户管理接口按调用者身份分流           |
| 租户隔离 | 用户管理 findById/状态/密码操作必须限定本租户（租户管理员）；系统管理员可跨租户                                      |
| 前端     | Users 页角色标签改为 系统管理员/普通管理员/普通用户；平台管理员视角显示「租户」列；创建表单按身份给角色选项          |
| 提权防护 | 租户管理员只能创建 `operator`；系统管理员创建的系统管理员同样 tenant_id=NULL                                         |
