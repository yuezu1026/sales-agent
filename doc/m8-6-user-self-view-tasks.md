# M8.6 用户管理视图收紧：普通用户只见自己、租户管理员排除自己

> 状态：✅ 已完成
> 创建：2026-08-13
> 前置：M8.4（管理员边界）、M8.5（系统管理员视图下拉）

## 一、需求原文

> 普通用户登录进去：用户管理只能看到自己，且只能修改自己的信息，包括密码重置，
> 而普通管理员，才能看到自己租户的普通操作员或者自己的租户的其他管理员，
> 且允许普通管理员对其租户内的用户进行密码重置或者禁用操作。

## 二、需求解读（设计决策）

| 角色                 | 用户管理页显示                                                       | 可执行操作                                                  |
| :------------------- | :------------------------------------------------------------------- | :---------------------------------------------------------- |
| 系统管理员（平台）   | 不变：视图下拉 + 系统管理员列表（可创建/重置密码）+ 所有用户只读视图 | 不变                                                        |
| 普通管理员（租户）   | **本租户用户，排除自己**（普通操作员 + 其他管理员）                  | 对其租户内用户重置密码 / 禁用启用（自己不在列表，天然排除） |
| 普通用户（operator） | **只显示自己一行**（只读信息）                                       | 「修改信息」按钮 → 跳转个人设置页（含改密）                 |

关键决策：

1. **后端 `GET /users` 放开登录**：由 `requireAdmin` 改为"仅登录校验"，按角色分派返回：
   - 系统管理员 → 平台系统管理员（不变）
   - 租户管理员 → `findByTenantId` **过滤掉自己**（需求强调"其他管理员"）
   - operator → 只返回自己
2. **后端 resetPassword/setStatus 不变**：租户管理员操作本租户任意账号（含其他管理员）已允许；列表不含自己 → 不会触发"不能操作自己"分支
3. **前端 Users.tsx 三视角渲染**：移除 `getRole() !== "admin" → navigate("/")` 限制，operator 也可进入；创建卡片仅管理员显示；operator 行提供「修改信息」跳转 `/settings`
4. **Nav.tsx**：operator 增加「用户管理」入口（非系统管理员分支均显示）；「系统设置」仍仅管理员
5. **自己不能禁用自己（补充确认）**：`setStatus` 对 `target==operator` 无条件 400「不能禁用当前登录账号」——无论租户内管理员数量（含仅 1 个），租户管理员都不能禁用自己，防止租户失管；前端列表已排除自己，天然不可触发
