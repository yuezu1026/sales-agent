## 一、为什么做签名激活码（背景）

现状问题：

- 激活码生成依赖**登录系统调 HTTP 接口**，且要**直连客户数据库** —— 卖给客户的场景不可接受
- 激活码无防伪造能力（客户可反推校验位算法）
- **运行期不比对指纹**：激活后换机器/MAC，系统照样能用（核心缺陷）

签名方案对比结论（用户确认采用）：

| 维度       | 现方案（查库）                       | 签名激活码方案                          |
| ---------- | ------------------------------------ | --------------------------------------- |
| 生成激活码 | 登录系统调接口，必须在客户系统上操作 | 厂商本地独立工具，完全不接触客户系统 ✅ |
| 数据库     | 工具/接口要连客户 DB                 | 工具零依赖，系统内置公钥即可 ✅         |
| 防伪造     | 客户拿到激活码后可反推校验位算法     | 无私钥无法伪造，改任意字符验签即失败 ✅ |
| 防篡改     | 只能存库里，客户端不可信             | 版别/有效期/序列号全在签名内，改不了 ✅ |
| 离线可用   | 依赖 DB 状态                         | 激活码自包含，验签 + 有效期即可判断 ✅  |

## 二、用户需求（原文整理）

1. **独立生成工具**：专门的应用/小工具/Java 命令产生 token，并定义 token 有效期
2. **激活页激活**：复制 token 到系统激活功能页面，点击激活即激活系统
3. **防重复使用**：token 激活后不能重复使用，只绑定那一次的 MAC 地址
4. **换机即失效**：MAC 一换，token 立刻失效，系统不能再用
5. **过期重激活**：token 过期后需重新激活（哪怕 MAC 没变）
6. **未过期续期**：未过期也可以重新续签

## 三、架构设计

### 3.1 总体架构

```
┌─────────────────────────┐        ┌──────────────────────────────┐
│  厂商本地（不接触客户）     │        │  客户系统（内置公钥）           │
│                         │        │                              │
│  license-tool.jar       │  激活码  │  激活页 /activate             │
│  ┌───────────────────┐  │ ──────▶ │  粘贴 → POST /api/license/    │
│  │ Ed25519 私钥       │  │        │    activate                  │
│  │ payload + 签名     │  │        │  ┌────────────────────────┐  │
│  └───────────────────┘  │        │  │ 内置公钥验签             │  │
│  私钥仅厂商持有           │        │  │ 序列号防重(DB UNIQUE)    │  │
└─────────────────────────┘        │  │ 指纹绑定(首次激活记录)    │  │
                                   │  └────────────────────────┘  │
                                   │  LicenseInterceptor 每次校验:  │
                                   │   ① 已激活? ② 未过期? ③ 指纹一致? │
                                   └──────────────────────────────┘
```

### 3.2 激活码格式

```
AICP-<payload段>-<签名段>
payload = 版本|版别|序列号|客户名|签发时间|到期时间
签名    = Ed25519 私钥对 payload 的签名（64 字节）
```

- 延续现有 `AIC{版别}-` 前缀风格（版别 B/P/E）
- payload + 签名用 Base32（去 0/O/1/I 混淆字符）编码，保证可手输
- 长度控制在 60 字符内（Ed25519 签名 64 字节 → Base32 约 103 字符，两段合计）

### 3.3 密钥管理

- 一次性生成 Ed25519 公私钥对：
  - 私钥：厂商本地保存（license-tool 使用，可加口令保护）
  - 公钥：`license-public.key` 打进后端镜像（resources 目录）
- 密钥文件格式：PEM（PKCS#8 / SPKI），JDK 21 原生支持 Ed25519（`KeyPairGenerator.getInstance("Ed25519")`），零第三方依赖

### 3.4 激活码生命周期

```
生成(厂商) → 首次激活(绑定设备指纹) → 使用中 → ①未过期续期(同设备换新码)
                                      ↘ ②过期 → 重激活(同设备换新码，MAC 不变也行)
```

| 场景                           | 行为                                                                    |
| ------------------------------ | ----------------------------------------------------------------------- |
| 首次激活                       | 验签通过 → 序列号唯一 → 绑定当前指纹 → status=active                    |
| 同设备重复激活（新码）         | 指纹一致 → **覆盖续期**（更新到期时间/序列号）                          |
| 同设备重激活（旧码已过期）     | 指纹一致 → 覆盖重激活，即使 MAC 没变 ✅                                 |
| 换设备激活（序列号已用）       | 指纹不一致 → 拒绝「已在其他设备激活」✅                                 |
| 运行期校验（每次核心接口调用） | ①未激活→拒 ②过期→拒（提示重新激活）③指纹≠绑定→拒（提示 License 失效）✅ |

### 5.1 license-tool 模块（M4-1a）✅

- `license-tool/LicenseTool.java`：单文件可执行（零第三方依赖），命令：
  - `keygen -o <dir>`：生成 Ed25519 公私钥对（PEM 输出）
  - `gen --private <pem> --edition pro --customer "XX公司" --serial Sxxx --days 365`：签发激活码
  - `verify --public <pem> <key>`：本地验签（开发调试用）
- `SignedLicense` 数据类：版别/序列号/客户名/签发时间/到期时间
- Base32 编解码（32 字符去混淆字符集，与后端一致）
- 运行：`java LicenseTool.java <cmd> ...`（无需构建 jar）

### 5.2 后端改造（M4-1b）✅

- `util/SignedLicenseCodec.java`：激活码解析 + 验签（内置公钥 resource，@PostConstruct 加载）
- `util/Base32.java`：Base32 编解码
- `util/SignedLicense.java`：payload record（v1|版别|序列号|客户名|签发日期|到期日期）
- `LicenseService.activate()` 重写：
  1. 验签失败 → 400「激活码签名校验失败，激活码无效」
  2. 已过期 → 400「激活码已过期」
  3. 序列号已存在且指纹不一致 → 400「该激活码已在其他设备激活，无法重复使用」
  4. 当前设备指纹一致（含已过期）→ 覆盖续期/重激活
  5. 首次 → 绑定指纹 + 插入
- `LicenseService.checkActive()` 增加：
  - 指纹比对：指纹 ≠ 绑定 → 400「设备指纹不匹配，License 已失效」
  - 过期检查：400「License 已过期，请重新激活」
- `License` 实体 + `V14__license_signed.sql`：`serial_no VARCHAR(64) UNIQUE`
- `V15__license_key_length.sql`：`license_key` 扩为 `VARCHAR(512)`（签名码 186 字符）
- `LicenseController.generate` 接口：**废弃移除**，保留 activate/status（status 增加 serialNo）
- `FingerprintUtil` 增强：容器内读取挂载的宿主机 `/etc/machine-id`（`/host-machine-id`），合并进指纹
