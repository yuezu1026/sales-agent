# AI智能获客助手产品规划方案

## 一、项目概述

- **项目名称**：AI智能获客助手（AI Sales Agent）
- **核心定位**：端到端的AI销售智能体，实现从线索发现到客户转化的全自动化闭环。
- **目标用户**：中小B2B企业、跨境电商卖家、SaaS服务商等需要持续获客的业务团队。
- **产品形态**：本地部署软件（非SaaS），采用"本地部署 + 云端AI"混合模式。后端打包为Docker镜像/JAR包，AI推理走云端大模型API。

## 二、业务可行性分析

### 2.1 业务逻辑闭环

产品通过自动化流程串联获客全链路：潜客挖掘（Function Calling + RAG）→ 个性化沟通（大模型生成邮件 + MCP协议发信）→ 订单预测与跟进（Agent编排 + Cron Job + Lead Scoring）。形成"发现-触达-转化"的完整业务闭环，降低人工干预成本。

### 2.2 市场验证

目标用户群体（中小B2B、跨境电商、SaaS服务商）普遍面临获客成本高、人工销售效率低的问题。本地部署模式满足企业对数据隐私的诉求，云端AI降低使用门槛，混合模式兼顾安全与智能，具备明确的市场需求。

### 2.3 核心难点与挑战

- **数据获取壁垒**：精准潜客数据是核心资源，公开渠道数据质量参差不齐，需对接合规第三方数据API。
- **触达渠道限制**：邮件、社交平台等渠道存在反垃圾机制，需遵循平台规则，避免账号封禁。
- **信任与转化**：AI生成的沟通内容需具备"人情味"，关键动作需人工确认，避免机械化触达导致客户反感。

## 三、技术可行性分析

### 3.1 整体架构：后端统一，前端分治

后端采用Spring Boot + Spring AI统一架构，确保核心业务逻辑一致；前端按终端分治：Web端使用React/Vue，小程序端使用Uni-app/Taro，App端使用Uni-app/React Native，实现"一套核心代码服务多端"，降低维护成本。

### 3.2 核心模块技术实现

- **潜客挖掘**：基于Function Calling调用外部数据API，结合RAG检索企业历史客户画像，精准匹配潜客。
- **个性化沟通**：大模型根据潜客特征生成定制化邮件/消息，通过MCP协议对接邮件服务商，自动发送并追踪打开率。
- **订单预测与跟进**：Agent编排多步骤跟进策略，Cron Job定时触发跟进任务，Lead Scoring模型动态评估客户意向，优先跟进高意向线索。

### 3.3 AI能力中台设计

用Spring AI构建统一的AI服务层，灵活对接Qwen-Max、DeepSeek等不同模型，实现缓存（减少重复调用成本）、限流（避免API超限）、计费（按Token/功能统计用量）等通用逻辑，所有业务系统统一调用该服务层，避免重复开发。

### 3.4 授权与防盗版机制

- **License验证**：客户购买后获得激活码，软件启动时验证License有效性。
- **硬件指纹绑定**：将License与设备硬件指纹绑定，防止一码多用。
- **云端API强制校验**：核心AI功能强制走云端API，即使软件被破解，无有效Token也无法使用核心功能，从根源上降低盗版风险。

### 3.5 技术栈总览

| 模块           | 技术选型                | 说明                     |
| :------------- | :---------------------- | :----------------------- |
| 后端框架       | Spring Boot + Spring AI | 统一业务逻辑，AI能力集成 |
| 前端（Web）    | React / Vue             | 管理后台与数据看板       |
| 前端（小程序） | Uni-app / Taro          | 移动端轻量级操作         |
| 前端（App）    | Uni-app / React Native  | 原生级体验的移动端       |
| AI模型         | Qwen-Max / DeepSeek     | 灵活切换，适配不同场景   |
| 部署方式       | Docker镜像 / JAR包      | 本地化部署，快速交付     |

## 四、商业模式

### 4.1 定价策略

| 版本   | 定价模式                   | 核心权益                            | 目标用户             |
| :----- | :------------------------- | :---------------------------------- | :------------------- |
| 基础版 | 一次性买断                 | 核心功能 + 终身使用（无AI智能分析） | 预算有限的初创团队   |
| 专业版 | 订阅制（月/年）或Token充值 | 含AI智能分析、邮件生成、订单预测    | 中型企业、跨境电商   |
| 企业版 | 高额项目费 + 维护费        | 私有化部署 + 定制开发 + 专属支持    | 大型企业、SaaS服务商 |

### 4.2 "AI能力封装"而非"Token倒卖"

不直接倒卖Token差价，而是将LLM能力封装进自有软件产品中，按功能/结果收费（如"生成100封个性化邮件""分析1000条潜客数据"）。Token只是底层成本，用户为"获客效果"付费，而非为"AI调用次数"付费，提升产品溢价空间。

### 4.3 现金流优势分析

基础版买断制提供初始现金流，专业版订阅制带来持续稳定收入，企业版定制项目贡献高额利润。混合模式兼顾短期回本与长期增长，降低一人公司的现金流压力。

## 五、合规与风险分析

### 5.1 数据隐私与法律

国内需遵守《个人信息保护法》，海外需符合GDPR/CAN-SPAM。应对策略：对接合规第三方数据API（如官方授权的企业信息查询接口），邮件中包含退订链接，敏感数据处理前进行脱敏。

### 5.2 平台规则风险

邮件、社交平台等渠道可能封禁自动化账号。应对策略：控制发送频率，模拟人工操作节奏，关键动作（如首次触达）需人工确认，避免批量机械化操作。

### 5.3 盗版与破解风险

本地部署软件易被破解。应对策略：核心AI功能强制走云端API，License与硬件指纹绑定，定期更新版本，破解版无法获取最新功能与AI服务。

### 5.4 风险应对策略

| 风险类型 | 风险描述                       | 应对策略                               |
| :------- | :----------------------------- | :------------------------------------- |
| 数据获取 | 公开数据质量差，合规数据成本高 | 对接合规第三方API，RAG结合企业自有数据 |
| 法律合规 | 违反个人信息保护法/GDPR        | 数据脱敏，邮件含退订链接，人机协同确认 |
| 账号封禁 | 自动化触达触发平台反垃圾机制   | 控制频率，模拟人工，关键动作人工确认   |
| 转化率低 | AI沟通内容缺乏人情味           | 优化Prompt，结合客户画像个性化生成     |
| 技术门槛 | 用户不会部署/使用              | 提供标准化部署文档，AI Agent辅助操作   |
| 盗版破解 | 本地软件被破解后免费使用       | 云端API强制校验，硬件指纹绑定          |
| 版本更新 | 用户不愿升级，导致功能碎片化   | 订阅制绑定最新版本，买断制提供有限更新 |

## 六、推荐产品方向与定位

### 6.1 核心策略调整

不做纯自动化黑盒，做"AI辅助高效获客工作台"。AI负责重复性工作（数据挖掘、邮件生成、跟进提醒），人工负责关键决策（确认触达、调整策略、处理异议），降低合规风险，提升转化信任度。

### 6.2 产品定位

面向中小B2B/跨境电商的"AI销售副驾驶"，而非"全自动销售机器人"。强调"人机协同""合规获客""效果可追踪"，解决用户对"AI获客=垃圾邮件"的刻板印象。

### 6.3 切入策略

- **垂直细分**：优先切入跨境电商或SaaS服务商，这两个群体获客需求明确，付费意愿强，且对本地部署接受度高。
- **数据合规化**：与合规数据服务商合作，提供"开箱即用"的潜客数据，降低用户使用门槛。
- **人机协同**：设计"AI建议 + 人工确认"的交互流程，让用户掌控获客节奏，建立信任。

## 七、产品路线图

### 7.1 第一阶段：MVP（Web端）

- 核心功能：潜客挖掘（Function Calling + RAG）、基础邮件生成、License验证。
- 目标：验证核心业务闭环，获取首批种子用户，收集反馈优化Prompt与数据源。
- 周期：2-3个月。

### 7.2 第二阶段：小程序端验证

- 核心功能：移动端线索查看、跟进提醒、简单邮件审批。
- 目标：验证移动端使用场景，提升用户粘性，测试小程序端获客渠道。
- 周期：1-2个月。

### 7.3 第三阶段：App端沉淀

- 核心功能：完整AI销售工作台、订单预测、Lead Scoring可视化。
- 目标：提供原生级体验，沉淀核心用户，推出专业版订阅。
- 周期：2-3个月。

### 7.4 第四阶段：智能化升级

- 核心功能：多模型灵活切换、AI自动优化跟进策略、企业版定制部署支持。
- 目标：提升AI能力中台复用性，拓展企业版客户，形成产品壁垒。
- 周期：持续迭代。

## 八、一人公司运营策略

### 8.1 交付标准化

- 后端打包为Docker镜像，提供一键部署脚本。
- 编写标准化部署文档与视频教程，降低用户上手成本。
- 核心代码统一，前端按终端分治，避免多端维护成本。

### 8.2 自动化运营

- 用AI Agent处理售前咨询（如"如何部署""价格多少"），减少人工客服压力。
- 自动化收集用户反馈，生成产品优化建议。
- 定期推送产品更新日志，保持用户活跃度。

### 8.3 获客渠道内容化

- 技术实战引流：撰写"Spring AI搭建AI智能获客助手""本地部署AI销售Agent"等技术文章，吸引开发者与潜在客户。
- 公域转私域：在技术社区（掘金、CSDN）、社交平台（知乎、小红书）发布内容，引导用户添加微信/加入社群，提供试用版与专属支持。
- 案例沉淀：收集种子用户成功案例，形成"获客效果对比"素材，增强说服力。
