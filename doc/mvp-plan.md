# 第一阶段 MVP（Web 端）核心功能规划

> 对齐《AI智能获客助手产品规划方案》第七章 7.1 第一阶段：MVP（Web 端）
> 周期：2-3 个月　目标：验证核心业务闭环，获取首批种子用户，收集反馈优化 Prompt 与数据源

## 一、MVP 目标与验收标准

### 1.1 业务目标

- 打通"发现 → 触达 → 转化"最小闭环，验证「AI 辅助高效获客工作台」的核心假设。
- 以「人机协同」为原则：AI 负责重复性工作（挖掘、生成、提醒），人工负责关键决策（确认触达、调整策略）。
- 获取 10~20 家种子用户试用，收集真实反馈迭代。

### 1.2 MVP 验收标准（DoD）

| 编号 | 验收项   | 说明                                                                    |
| :--- | :------- | :---------------------------------------------------------------------- |
| V1   | 潜客闭环 | 能通过 Function Calling 从数据源挖出潜客 → 入库 → 列表展示 → 打标管理   |
| V2   | 邮件闭环 | 能基于潜客画像生成个性化邮件 → 人工确认 → SMTP 发送 → 记录打开/回复状态 |
| V3   | 授权闭环 | License 激活、硬件指纹绑定、过期/失效校验生效                           |
| V4   | 人机协同 | 所有外发动作必须经人工确认，无自动外发                                  |
| V5   | 用量可查 | 后台可查看 Token 消耗与邮件发送统计                                     |

### 1.3 MVP 明确不做（边界）

- ❌ 小程序端 / App 端（第二阶段再做）
- ❌ 订单预测、Lead Scoring（第三阶段）
- ❌ 多模型自动切换（第一阶段固定 Qwen-Max 或 DeepSeek 其一）
- ✅ MCP 协议对接邮件服务商（M2-1.6 已升级：本服务自建 MCP Server 暴露 /mcp，抓取客户回复邮件；发送仍用标准 SMTP）
- ❌ 多租户、复杂 RBAC 权限（先单组织 + 简单账号）
- ❌ 自动化营销流程编排（先手动触发 + 简单跟进提醒）

## 二、核心功能模块

### 2.1 潜客挖掘模块（核心）

| 功能点       | 说明                                                                                    | 优先级 |
| :----------- | :-------------------------------------------------------------------------------------- | :----- |
| 潜客检索     | 输入行业/地区/关键词/规模等条件，Function Calling 调外部数据 API（先接 1 家合规数据源） | P0     |
| RAG 客户画像 | 导入企业自有历史客户 CSV → 向量化 → 检索相似客户画像辅助筛选                            | P0     |
| 潜客入库管理 | 列表/搜索/筛选/分页、字段校验、去重                                                     | P0     |
| 潜客打标     | 状态流转：新线索 → 已触达 → 有意向 → 已转化 / 无效                                      | P1     |
| 潜客导出     | CSV 导出                                                                                | P1     |
| 数据源配置   | 第三方数据 API Key 配置（MVP 阶段 1 个数据源即可）                                      | P1     |

**流程**：配置数据源 → 输入挖掘条件 → Function Calling 拉取 → RAG 匹配自有画像打分 → 人工筛选入库 → 打标管理。

### 2.2 邮件生成与发送模块

| 功能点        | 说明                                                                                         | 优先级 |
| :------------ | :------------------------------------------------------------------------------------------- | :----- |
| 邮件模板库    | 预置首触达/跟进/节日问候等基础模板                                                           | P0     |
| AI 个性化生成 | 基于潜客画像 + 模板，大模型生成定制邮件（支持改写、语气调节）                                | P0     |
| 延续性生成    | 基于该客户沟通记录（跟进/已发邮件/回复）拼时间线续写邮件（M2-1.7，业务数据即记忆，无需 RAG） | P1     |
| 草稿统一管理  | 跨客户邮件草稿页：搜索/状态筛选/确认/改回/删除（M2-1.7 补充，导航「草稿箱」/drafts）         | P1     |
| 人工编辑确认  | 邮件发送前必须人工预览/编辑/确认（人机协同红线）                                             | P0     |
| SMTP 发送     | 配置发信邮箱，单发/批量小量发送（限频）                                                      | P0     |
| 发送记录      | 记录发送状态、失败原因、重试                                                                 | P1     |
| 打开率追踪    | 埋点统计打开/点击/回复（退订链接必须包含）                                                   | P1     |
| 发送频率控制  | 每账号每日上限，模拟人工节奏，防止封号                                                       | P1     |

### 2.3 License 验证模块

| 功能点           | 说明                                      | 优先级 |
| :--------------- | :---------------------------------------- | :----- |
| 激活码校验       | 激活码格式校验 + 云端/离线校验            | P0     |
| 硬件指纹绑定     | 采集设备指纹，与 License 绑定，防一码多用 | P0     |
| License 状态管理 | 查看剩余天数/到期提醒/续期                | P1     |

### 2.4 AI 能力中台（最小版）

| 功能点         | 说明                                                | 优先级 |
| :------------- | :-------------------------------------------------- | :----- |
| 统一模型封装   | Spring AI 封装单一模型（Qwen-Max 或 DeepSeek 选一） | P0     |
| Prompt 管理    | 邮件生成/潜客画像等场景 Prompt 可配置化             | P1     |
| Token 用量统计 | 每次调用记录 token 消耗，后台可查                   | P1     |
| 缓存与限流     | 重复请求缓存、API 限流防超限                        | P2     |

### 2.5 基础支撑

- 账号登录（简单用户名密码 + 会话）
- 系统配置页（AI 模型 Key、SMTP、数据源 API）
- 简单数据看板（潜客数量、邮件发送数、打开率、Token 消耗）
- Docker 一键部署 + 初始化脚本

## 三、MVP 技术栈建议

| 层       | 选型                       | 说明                                          |
| :------- | :------------------------- | :-------------------------------------------- |
| 后端     | Spring Boot + Spring AI    | 统一业务逻辑，AI 能力集成                     |
| 前端     | React（或 Vue）            | 管理后台 + 数据看板                           |
| 数据库   | PostgreSQL（或先 SQLite）  | 一人公司 MVP 可先 SQLite 降低运维             |
| 向量检索 | pgvector / Chroma          | 客户画像 RAG 检索                             |
| 数据源   | 1 家合规第三方企业数据 API | 先接一家验证流程                              |
| 邮件     | SMTP（javax/jakarta mail） | 发送用 SMTP；回复邮件抓取已升级 MCP（M2-1.6） |
| 部署     | Docker Compose 一键部署    | 本地部署交付                                  |

## 四、里程碑拆分（2-3 个月）

### M1：骨架与授权（第 1 个月）

- 项目脚手架（后端 + 前端 + Docker）
- License 激活 / 硬件指纹绑定
- 账号登录、系统配置
- AI 能力中台最小版（模型封装 + 用量统计）
- ✅ 里程碑验收：可部署、可激活、可登录

### M2：潜客挖掘（第 1.5~2 个月）

- 数据源对接（Function Calling）
- RAG 客户画像（历史客户导入 + 向量化 + 检索）
- 潜客入库管理、打标、导出
- ✅ 里程碑验收：V1 潜客闭环跑通

### M3：邮件闭环 + 种子用户（第 2.5~3 个月）

- 邮件模板 + AI 生成 + 人工确认
- SMTP 发送 + 限频 + 记录
- 打开率追踪、退订
- 简单数据看板
- ✅ 里程碑验收：V2 邮件闭环跑通 → 邀请 10~20 家种子用户试用

## 五、MVP 成功指标

| 指标           | 目标值                    | 说明                                   |
| :------------- | :------------------------ | :------------------------------------- |
| 种子用户       | 10~20 家                  | 覆盖跨境电商 / SaaS 服务商两个垂直领域 |
| 邮件打开率     | ≥ 30%                     | 对比行业均值，验证 AI 邮件质量         |
| 潜客有效线索率 | ≥ 10%                     | 挖到的潜客中真正有意向的比例           |
| 使用留存       | 周活跃 ≥ 50%              | 用户持续使用，验证需求真实性           |
| 反馈收集       | 每种子用户 ≥ 3 条有效反馈 | 用于优化 Prompt 与数据源               |

## 六、风险与应对（MVP 阶段）

| 风险                | 应对                                                  |
| :------------------ | :---------------------------------------------------- |
| 数据源质量差/无数据 | 提前联系 2-3 家合规数据商，准备 CSV 手动导入兜底      |
| 邮件发送进垃圾箱    | 控制频率、SPF/DKIM 配置、提供退订、先小批量灰度       |
| License 被破解      | 核心 AI 功能强制走云端 API 校验，本地不存完整模型能力 |
| 一人开发进度风险    | 严格砍需求（见"不做清单"），先跑通闭环再优化          |
| 用户不会部署        | Docker 一键部署脚本 + 图文教程 + 视频教程             |
